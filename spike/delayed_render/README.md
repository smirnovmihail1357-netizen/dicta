# Спик delayed render — протокол прогона на Windows-машине

> **ЧЕСТНАЯ ШАПКА.** Это **эксперимент, не production-код**. Результат фиксируется
> в `.planning/phases/07-windows-diktovka-mvp/07-SPIKE-RESULT.md` **до** написания
> вставки `inject_win` (locked 5 / Must-NOT 8). Не заполняйте таблицу «на глаз»:
> перенесите сюда только то, что реально напечатал бин на вашей машине. Если что-то
> не сработало — честно запишите отказ, это важнее зелёной картинки.

Спик — маленький standalone-бин (только `windows-rs 0.58`, **без enigo / cpal /
interprocess**). Он проверяет механизм `SetClipboardData(CF_UNICODETEXT, NULL)`
(promise) + `WM_RENDERFORMAT` и собирает 9 живых замеров для production-вставки.

## 1. Как собрать и запустить

На Windows-машине (CI-раннер headless — GUI-замеры там НЕвоспроизводимы):

```powershell
cd spike\delayed_render
cargo build --release
.\target\release\dicta-spike-delayed-render.exe --mode=user --window=message-only
```

Аргументы:

| Флаг | Значения | Смысл |
|------|----------|-------|
| `--mode=` | `user` (по умолчанию) / `send` | `user` — вы сами жмёте Ctrl+V в целевом окне; `send` — спик шлёт Ctrl+V через `SendInput` с меткой `dwExtraInfo` |
| `--window=` | `message-only` (по умолчанию) / `hidden` | тип окна-владельца буфера: `HWND_MESSAGE` vs скрытое `WS_OVERLAPPED` без `WS_VISIBLE` (замер 7) |
| `--text=` | любая строка | тестовый «транскрипт»; **содержимое в логи не попадает**, печатается только длина |

`dictad.exe` скачивать **не обязательно** — спик независим от демона и от
артефакта `dictad-windows-x64`. Достаточно Rust (rustup stable) и этого каталога.

Бин печатает в stdout строки с префиксом `SPIKE | ` — **копируйте их построчно**
в колонку «факт» соответствующих строк `07-SPIKE-RESULT.md`. Содержимое буфера не печатается
никогда (даже в эксперименте).

## 2. Порядок прогона (обязательный)

Для **каждого** окна-владельца (`message-only`, затем `hidden`) прогнать
**оба режима** (`user`, затем `send`) на каждом целевом окне:

1. **Notepad** — обычное окно, базовый кейс.
2. **Chromium-браузер** (Chrome/Edge) — probe-then-read, ожидается **≥2** `WM_RENDERFORMAT`.
3. **Windows Terminal** — проверить Ctrl+V и Ctrl+Shift+V; зафиксировать, какой сработал.
4. **elevated-Notepad** (Запуск от имени администратора) — UIPI: вставка **не должна**
   проходить; зафиксировать факт тихого отказа, а не «успех».
5. **Зажатый модификатор** — перед Ctrl+V удерживайте Ctrl/Win; зафиксировать,
   искажается ли аккорд.

Между кейсами закрывайте предыдущее целевое окно, чтобы фокус был однозначным.
После каждого прогона бин ждёт 5 с и печатает `=== 5s SETTLE LOG ===`.

## 3. Девять замеров (что заполнить в `07-SPIKE-RESULT.md`)

| № | Что делаем | Что скопировать в «факт» |
|---|------------|--------------------------|
| 1 | Старт бина, до promise | строку `baseline 1:` — длина исходного `CF_UNICODETEXT` (или «отсутствует») |
| 2 | promise + оптауты | строку `promise 2:` и все четыре `optout 2[0..3]:` (fmt id, `promise_null_ok=true`) |
| 3 | Проверка успеха | все три строки `check 3:` — `GetLastError`, `IsClipboardFormatAvailable`, `GetClipboardOwner` (совпало ли с hwnd) |
| 4 | Вставка | строки `WM_RENDERFORMAT ... render#N` — `t1-t0`, `t2`, **счётчик повторных рендеров** (у Chromium ожидается ≥2), для user и send режимов отдельно |
| 5 | Тишина 5 с | блок `=== 5s SETTLE LOG ===` + строка `summary:` — фактический settle; сравнить с потолком `clipboard_restore_ms=2500` |
| 6 | Кейсы-цели | по строке `insert 4:` на каждый из 5 кейсов × 2 режима: что реально вставилось / не вставилось |
| 7 | Тип окна | сравнить прогоны `message-only` и `hidden`: в каком `WM_RENDERFORMAT` пришёл за 10 с; записать рабочий тип |
| 8 | Перед выходом | все строки `WM_RENDERALLFORMATS fmt=... res=OK` и `all_formats_rendered=` из `summary:` (не отрендерить = потеря данных) |
| 9 | Второй способ рендера + оптауты | (а) в отдельном прогоне, пока бин ждёт вставку, выполнить `powershell -NoProfile -Command "Get-Clipboard"` — срос ли счётчик рендеров; (б) после прогона нажать **Win+V** — появился ли транскрипт в истории (должен отсутствовать); записать честно |

## 4. Куда копировать вывод

1. Откройте `.planning/phases/07-windows-diktovka-mvp/07-SPIKE-RESULT.md`.
2. Для каждой из 9 строк замените маркер `факт: <заполнить>` на скопированную
   из stdout строку (сохраняя префикс `факт: ` — его гребёт гейт Task 2).
3. Заполните секцию «Выводы для inject_win»: тип окна, фактический settle,
   ≥2 рендеров у Chromium — да/нет, поведение `WM_RENDERALLFORMATS`, PowerShell-нюанс.
4. Убедитесь, что маркеров `TBD` / `заглушка` / `<заполнить>` не осталось.

## 5. Честность — главный артефакт

- `SetClipboardData(NULL)` в `windows-rs` приходит как `Err` — это **ожидаемый**
  Win32-«успех» (NULL на успехе); успех проверяйте по `IsClipboardFormatAvailable`
  и `GetClipboardOwner`, **не** по `GetLastError`.
- Если elevated-Notepad всё же принял вставку или Win+V показал транскрипт —
  запишите это как факт. Оптауты кооперативны; расхождение важнее « зелёного » результата.
- Если `WM_RENDERFORMAT` не пришёл в message-only за 10 с — перейдите на `hidden`
  и зафиксируйте оба факта. production-тип окна берётся **только из замера 7**.
