# Производительность: потребление CPU / памяти

Замеры потребления dictad и dicta-ui при работе оверлея (режим recording,
полная перерисовка 520×34 каждые 100 мс), в т.ч. под нагрузкой системы.

## Окружение

| Параметр | Значение |
|---|---|
| Дата | 2026-11-16 |
| CPU | Ryzen, 32 ядра (`nproc`=32) |
| RAM | 60 ГБ |
| GPU (whisper) | Radeon 610M iGPU (`gpu_device = 0`) |
| Стек | Arch, KDE Plasma 6 (KWin, Wayland), PipeWire |
| Версия dicta | v0.3.0 + скругление углов оверлея (premultiplied-alpha blend, `round_rect`) — замеры на этой сборке |
| Модель whisper | ggml-medium-q5_0, `use_gpu = true`, `n_threads = 8`, `beam_size = 5` |
| Конфиг | `inject_mode = "paste"`, `paste_keys = "ctrl+v"`; auto_stop: true / level 0.22 / after 1500 мс / grace 1200 мс; `min_level = 0.35` |
| Метод | Дельта `utime+stime` из `/proc/<pid>/stat` с шагом 1 с; load average из `/proc/loadavg`; RSS через `ps -o rss`. Нагрузка системы — busy-циклы на отдельных ядрах (8 и 16 штук) |

## Результаты

### 1. Recording (оверлей рисуется, 100 мс цикл)

| Нагрузка системы | load1 (из 32) | dictad CPU | dicta-ui CPU |
|---|---|---|---|
| Без нагрузки | ~3 | 0–2% одного ядра | 2–4% одного ядра |
| 8 busy-циклов | 2.8 → 3.7 | 0–2% | 2–4% |
| 16 busy-циклов | 3.3 → 6.6 | 0–1% | 2–4% |

### 2. Память (RSS)

| Процесс | Idle | Recording ~40 с | Во время инференса |
|---|---|---|---|
| dictad | 65–67 МБ | 65–67 МБ (утечки нет) | ~97 МБ (whisper), обратно в idle |
| dicta-ui | 5 МБ | 5 МБ | 5 МБ |

### 3. Инференс (stop → распознавание → idle)

- whisper medium-q5_0 на iGPU под нагрузкой load1≈5.2 (8 busy-циклов):
  **~3.2 с** от `dictactl stop` до возврата в idle.
- CPU-нагрузка dictad при инференсе минимальная: тяжёлая часть на GPU;
  CPU тратится на ресемплинг и подготовку аудио.
- При `min_level` по умолчанию (0.35) тишина фильтруется до инференса
  («слишком тихо (уровень 0.281 < 0.35) — распознавание пропущено») —
  в этом случае GPU вообще не задействуется.

## Выводы

- dicta не нагружает систему: оверлей 2–4% одного ядра (это штатная работа —
  полный перерендер с 2×2 суперсэмплингом скруглений + polling статуса 10 Гц),
  демон 0–2%. На 32 ядрах вклад в общую нагрузку ~0.1%.
- Память стабильна, утечек при длительной записи не обнаружено.
- Инференс не чувствителен к CPU-нагрузке системы (GPU-путь).

## Анимация появления (добавлена после этих замеров)

Поверхность оверлея стала 520x54 вместо 520x34 (1.6x пикселей на кадр): нижние 12 px —
«карман», из которого пилюля выезжает, верхние 8 px — запас под overshoot. Место покоя
пилюли не изменилось (низ пилюли в 14 px от кромки экрана; в KWin 6 при 1440 px —
строки 1396-1425).

Перерисовка теперь идёт на 16 мс кадра только во время анимации (~45 к/с, 260 мс появления
и 170 мс ухода), в покое и при записи — по-прежнему раз в 100 мс. Замер на той же машине,
debug-сборка, демон подменялся подставным сокетом, состояние чередовалось
recording/idle каждые 500 мс, 6 с: 46 тиков CPU (460 мс) с анимацией против 10 тиков
(100 мс) при `DICTA_ANIM=0` — то есть ~30 мс CPU на одну анимацию, ~0.3% ядра в среднем.
Запись без анимации: 15 тиков за 5 с (3% одного ядра), RSS оверлея 4 МБ — как и раньше.

## Панель настроек (добавлена после этих замеров)

Вторая layer-поверхность того же процесса, 520x220 (панель 158 px + «карман» под пилюлю).
Замер на той же машине, debug-сборка, демон idle, панель открыта: 19% одного ядра — пока
кадр панели перерисовывался каждые 100 мс ради неподвижных кнопок (114 400 пикселей на кадр:
`round_rect` со скруглениями и подписи кнопок).

Исправлено подписью кадра: пока заголовок, строка ответа демона и все подписи кнопок не
меняются, второй буфер не создаётся и не отправляется. Тот же замер после исправления:

| Состояние | dictad | dicta-ui |
|---|---|---|
| панель закрыта | 0–1% | 0% |
| панель открыта, неподвижна | 0–1% | 0% |
| анимация открытия (260 мс) | 0–1% | ~15% во время подъёма |

То есть панель в простое не стоит ничего; CPU тратится только на её подъём/уход и на
перерисовку после реального изменения настроек. RSS оверлея с панелью: 6.8 МБ (было 4–5 МБ,
рост — второй буфер SlotPool на 457 КБ).

## Возможные оптимизации (не выполнены)



1. Рисовать только при изменении уровня/текста, а не каждые 100 мс
   (режет ~0.5–1% ядра).
2. Замораживать кадр при тишине (level не меняется).

## Как повторить замер

```sh
# busy-нагрузка на N ядер на 14 секунд
for i in $(seq 16); do timeout 14 bash -c 'while :; do :; done' & done

# дельта CPU раз в секунду (jiffies: 100 = 1% ядра)
D=$(pgrep -x dictad); U=$(pgrep -x dicta-ui)
get() { awk '{print $14+$15}' /proc/$1/stat; }
pd=$(get $D); pu=$(get $U)
for i in $(seq 12); do
  sleep 1
  nd=$(get $D); nu=$(get $U)
  echo "t=$i dictad=$((nd-pd))% ui=$((nu-pu))% load1=$(cut -d' ' -f1 /proc/loadavg)"
  pd=$nd; pu=$nu
done

# память
ps -o rss= -p $D; ps -o rss= -p $U   # значения в КБ

# инференс под нагрузкой (на тишине: min_level = 0.15 во временной копии
# конфига, после теста конфиг вернуть!)
dictactl start; sleep 5; dictactl stop
```

Примечание: при тесте инференса на тишине whisper выдаёт галлюцинации — это
ожидаемо и не влияет на корректность замера нагрузки.
