# SECURITY

dicta записывает микрофон и печатает вместо тебя — это чувствительные права, поэтому:

- **Сокет демона** создаётся в `$XDG_RUNTIME_DIR` (обычно `/run/user/1000`, каталог `0700`).
  Любое приложение от твоего UID может послать демону команду — как и с любым другим сокетом в
  этом каталоге. Не запускай dicta в каталоге с мировыми правами и не переноси сокет в `/tmp`.
- **Буфер обмена** на время вставки подменяется и возвращается обратно через
  `clipboard_restore_ms` (2500 мс по умолчанию). Если в буфере были секреты, они будут
  временно заменены распознанным текстом — и наоборот, распознанный текст виден всем
  приложениям с доступом к буферу. Режим `inject_mode = "clipboard"` не нажимает клавиши, но
  оставляет текст в буфере.
- **uinput-клавиатура**: виртуальное устройство `dicta-keyboard` видно всем процессам с доступом
  к `/dev/input` как обычная клавиатура. Оно ничего не печатает, пока демон не решит вставлять.
- **Микрофон**: запись начинается только по команде (клавиша/адаптер/CLI). Демон не слушает
  постоянно; буферится только текущая сессия диктовки, временный WAV удаляется после обработки.
- **Модель и аудио никуда не отправляются**: распознавание локальное (whisper-rs). Сетевых
  вызовов у демона нет.
- **AT-SPI2-вставка** (`inject_mode = "atspi"`): текст пишется напрямую в редактируемый объект
  через сессионный bus доступности (`org.a11y.atspi.EditableText`). Этот bus читается и пишется
  всеми процессами сессии — то, что видно фокусному окну, доступно и любому другому процессу
  пользователя. Режим включён только явно и пишет только в фокусный объект с ролью поля ввода.

Уязвимости: private report через GitHub Security Advisories (Security -> Report a vulnerability).
Не выкладывай незакрытые дыры в issues.
