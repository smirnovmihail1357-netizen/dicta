# Feature Research

**Domain:** Контрольное окно (control-center) для системного голосового диктанта — Flutter desktop app поверх существующего демона dictad
**Researched:** 2026-11-22
**Confidence:** HIGH (по конкурентам и UI-паттернам) / MEDIUM (по потоковому выводу и маршрутизации моделей)

Контекст: dicta уже имеет ядро (демон + оверлей + CLI + egui-настройки). Веха v1.1 добавляет dicta-app — единый центр управления в духе FlClash. Ниже — только НОВЫЕ фичи приложения, с привязкой к существующему протоколу сокета.

## Ландшафт: как устроены контрольные окна диктант-приложений

Обзор Superwhisper (macOS/Windows, самый зрелый локальный диктант), Whispering/Epicenter (open-source, local-first), stttui (терминальный local STT), WM Keyboard (офлайн-клавиатура с маршрутизацией whisper-моделей) и FlClash (образец UI для control-center):

- **Приложение живёт в трее, окно — опционально.** Диктовка всегда стартует хоткеем из любого окна; control-окно открывается для настройки, диагностики и просмотра истории. Superwhisper: «Home in settings» + меню-бар + мини-окно записи; Whispering: «Press shortcut → speak → get text», окно нужно для истории и настроек.
- **Дашборд минимален:** состояние (запись/обработка/ошибка), кнопка записи, уровень сигнала, последний результат. Ни у одного конкурента дашборд не перегружен — перегруз убивает «тихое» приложение.
- **История — центральная ценность окна.** Superwhisper 8.0 переписал History: поиск по диктовкам, мультивыбор, удаление, репроцессинг; быстрый доступ из трёх мест (Home → «See all», меню-бар, мини-окно). Ревью efficient.app называет копирование из истории «абсолютно необходимой» фичей: «if something doesn't paste, you can copy and paste it instead of starting over».
- **Управление моделями — библиотека, а не одна строка конфига.** Superwhisper: Models library (browse/download/remove/favorites/compare); WM Keyboard: каталог с подсказками размера и маршрутизация модели по языку.
- **Трей — короткое меню (5–8 пунктов) с живым состоянием.** FlClash: start/stop + toggle-опции + видимость окна прямо в трее; иконка отражает состояние (цветные + монохромные варианты).

### Differentiators (Competitive Advantage)

Ценность dicta — «нажал-сказал-получил, локально, без облака». Дифференциаторы выбираем под это ядро.

| Feature | Value Proposition | Complexity | Notes / зависимость от dictad |
|---------|-------------------|------------|-------|
| Быстрое переключение модели из дашборда (чип/дропдаун) и из трея | stttui хвастается «on-the-fly model switching»; у нас `set model` + `schedule_engine_reload` уже работают — дёшево и заметно | LOW–MEDIUM | Существующие `set` + guard «reload отказывает при записи» (показывать состояние загрузки: reloading AtomicBool в статусе?) — возможно, лёгкое расширение ответа status |
| Калибровка порога тишины из UI (визуальный мастер: «говорите… молчите…») | `dictactl calibrate` уже существует, но только для CLI-пользователей; визуальная калибровка — то, за что платят в Superwhisper Advanced settings | MEDIUM | Логика в dicta-core есть; приложению нужен поток уровней (`status.level`) + `set min_level` |
| Диагностика окружения на дашборде: pw-record, wl-copy, /dev/uinput, группа input, адаптер DE, фокус-кэш | dicta зависит от внешних процессов и прав (сокет-подсказки уже в логах демона) — ни один конкурент не имеет такого «здоровья системы» в UI; killer-фича для Linux-пользователей | MEDIUM | Read-only проверки клиентские + вывод last_error демона. Снимает главный источник «не работает» |
| Настройка paste_keys по приложениям (таблица «приложение → комбинация» + подсказка фокуса) | dicta единственный решает проблему «в каком окне вставлять» на Wayland — показать это в UI значит продать главную фишку | MEDIUM | `paste_keys` в EDITABLE_KEYS есть; фокус-кэш `~/.cache/dicta/focus` читается клиентом |
| Словарь/initial prompt (свои термины в whisper-промпт) | Замер (gist, RTX 4050): «without prompt even the big models miss jargon» — промпт важнее размера модели; Superwhisper продаёт custom vocabulary как фичу Free-плана | MEDIUM | whisper.cpp поддерживает initial prompt, но ключа нет в EDITABLE_KEYS → нужно небольшое расширение демона (новый ключ + ENGINE-подобная семантика). Отложить до подтверждения |
| Частичный/потоковый показ текста во время Transcribing | Superwhisper Pro «Realtime transcription», WM Keyboard «Words while it works» — главная платная фича конкурентов; диктант-UX сильно улучшается | HIGH | Требует пересборки inference в демоне (chunked/streaming whisper) — **противоречит ограничению вехи «не трогать демон»**. Компромисс v1: показывать состояние «распознаётся… N c» + текст сразу по готовности (уже есть через status). Полный стриминг — следующая веха |
| Модели по языкам / маршрутизация (WM Keyboard: pin модели на язык + fallback-цепочка) | Русский + английский у одного пользователя: multilingual vs `.en` на tiny/base заметно точнее | HIGH | Один `model` в конфиге, языковой ключ `language` есть. Полная маршрутизация = расширение демона. Дешёвая версия: селектор language + подсказка «для русского нужен multilingual» в браузере моделей |
| Автозапуск приложения + onboarding-чеклист (первый запуск: права, модель, тест вставки) | «Press shortcut → speak → get text» должен заработать за 2 минуты у новичка | MEDIUM | Автостарт демона уже есть (`--install-autostart`); приложению — свой .desktop + чеклист из диагностики выше |

### Anti-Features (Commonly Requested, Often Problematic)

Фичи, которые выглядят привлекательно, но ломают dicta. Документируем, чтобы не разбухнуть.

| Feature | Why Requested | Why Problematic | Alternative |
|---------|---------------|-----------------|-------------|
| Облачные STT-провайдеры (Groq/OpenAI/BYOK) | Superwhisper/Whispering так делают, «точность large бесплатно» | Ломает local-first ценность dicta («ничто не покидает устройство» — главный аргумент Superwhisper Free); добавляет настройки ключей, сеть, обработку отказов; у нас Vulkan-GPU уже даёт ~200 мс | Ничего: whisper.cpp локально. Если приспичит — отдельная веха, не смешивать с control-center |
| AI-постобработка (LLM-чистка текста, «modes») | «Fix grammar, translate» у Whispering/Superwhisper | Вторая модель в петле = задержка × 10, облако или гигабайты локально; чужая ценность — dicta про скорость и предсказуемость | Уже есть `filter::clean` от галлюцинаций; словарь-промпт (differentiator) закрывает жаргон без LLM |
| Запись встреч / файловая транскрипция | Superwhisper Meetings — модно | Whispering прямо позиционируется «for quick transcriptions, not long recordings»; длинные сессии = другие требования (VAD-сегментация, диаризация, память), ломает дизайн watchdog | Остаться в нише коротких диктовок; meetings — вне продукта |
| Хранение аудио в истории по умолчанию | «Послушать, что я сказал» (Superwhisper хранит записи) | Приватность (голс на диске навсегда) + гигабайты; dicta удаляет WAV в Drop не случайно | История = текст + метаданные. Аудио — опция off по умолчанию, если вообще |
| Волновая форма с воспроизведением в окне | «Красивый дашборд» | Контрольное окно ≠ аудиоредактор; проигрывание — функция истории аудио (см. выше) | Живой уровень (RMS-волна как в оверлее) — достаточно и дёшево |
| Статистика (WPM, слов за неделю, «время сэкономлено») | Superwhisper Home показывает | Милый bloat: экран ради экрана, работа над хранением агрегатов | Нет. Дашборд — про текущую диктовку, не о прошлом |
| Свободный редактор config.toml в приложении | FlClash имеет code editor для YAML | dicta-инвариант: «панель нельзя привести в состояние, которого демон не придерживается» — валидация в `parse_change`. Свободный редактор это ломает | Формы по EDITABLE_KEYS + живой `set`; продвинутым — файл руками в редакторе |
| WebDAV/облачный backup настроек | FlClash feature | Настройки — один TOML; экспорт/импорт файла хватит с избытком | Кнопка «открыть config.toml» / копия файла |
| Повторная обработка старой диктовки другой моделью (Superwhisper reprocess) | «Прогнать через новую модель» | Требует хранить аудио (см. выше) + очередь inference в демоне | Не строить; «вставить заново» закрывает 90% сценария |

## Feature Dependencies

```
[Оболочка: сайдбар + темы]
    └──requires──> [IPC-клиент к сокету dictad] (вне этого файла, см. STACK)

[Дашборд состояния] ──requires──> [IPC-клиент] (status/toggle/start/stop/cancel — есть)
[Живой уровень]     ──requires──> [Дашборд] (тот же poll status)
[Текст+re-insert]   ──requires──> [Дашборд] (status.text + inject — есть)

[История] ──requires──> [Захват завершённых диктовок]
                            ├── вариант A: пассивный poll (status: переход Transcribing→Idle с текстом) — протокол не трогаем
                            └── вариант B: additive-команда/JSONL в демоне — против ограничения вехи
[Поиск/удаление]     ──requires──> [История] (клиентский store: SQLite/JSONL в приложении)
[Re-insert из истории] ──requires──> [История] + [inject — есть]

[Настройки (17 ключей)] ──requires──> [settings/set — есть]
[Браузер моделей]      ──requires──> [Настройки] (HF API — клиентский)
[Удаление моделей]     ──requires──> [Браузер моделей] (файлы в папке моделей, демона не касается)
[Быстрый свитч модели] ──requires──> [Управление моделями] + [set model — есть; guard reload]

[Трей] ──requires──> [IPC-клиент] + [Оболочка] (действия = существующие команды)
[Свернуть в трей] ──requires──> [Трей]

[Hotkey-экран] ──requires──> [Определение рабочего пути: evdev-хоткей vs DE-адаптер]
[Словарь-промпт] ──requires──> расширение демона (новый ключ) — отложить
[Потоковый текст] ──requires──> переделка inference демона — конфликтует с ограничением вехи

[Диагностика окружения] ──enhances──> [Onboarding] и закрывает главный источник обращений
[Калибровка] ──enhances──> [Дашборд] (использует тот же level-poll)
```

### Dependency Notes

- **Захват истории — ключевая развилка.** Демон не хранит историю (WAV удаляется, живёт last_text). Ограничение вехи: «поверх существующего демона без изменения протокола сокета». Вариант A (пассивный): приложение опрашивает `status` и фиксирует переход Transcribing→Idle, когда появился новый `text` → пишёт в свой store (SQLite/JSONL). Минус: приложение должно быть открыто/в трее, чтобы ничего не пропустить. Вариант B (демон пишет JSONL) надёжнее, но трогает демона. Рекомендация: v1 — вариант A (трей делает приложение практически всегда живым), не замыкая дверь для B.
- **Hotkey-экран зависит от фактического пути ввода.** evdev-хоткей слушает демон при старте — ключа в EDITABLE_KEYS нет; смена = правка config.toml + рестарт демона (или DE-адаптер, который вообще не в демоне). UI обязан: (1) показать, какой путь активен; (2) для evdev — предупреждение «применится после перезапуска демона»; (3) для адаптера — сгенерировать/показать нужный скрипт. Ложный «rebind работает сразу» — худший вид обмана.
- **Настройки модели во время записи/распознавания:** `set` по ENGINE_KEYS отклоняется (reloading/занятость) — UI должен показывать это состояние, а не молча глотать.
- **Трей и демон — разные процессы.** Выход из dicta-app не останавливает диктовку. Это фича (диктовка переживает окно), но подпись в трее должна это прояснять; НЕ добавлять «Остановить демон» в трей без явного решения (закономерный запрос — но ломает «демона не трогаем»).

## MVP Definition

### Launch With (v1)

Минимум, закрывающий все Active-пункты PROJECT.md:

- [ ] Оболочка: сайдбар (Дашборд/История/Модели/Настройки), Material You, светлая/тёмная — визуальный паритет с FlClash задан как цель пользователем
- [ ] Дашборд: состояние, уровень, секунды, старт/стоп/отмена, последний текст + копировать/вставить заново, строка ошибки
- [ ] История: журнал + поиск + копировать/вставить заново/удалить; пассивный захват через опрос `status`
- [ ] Настройки: все EDITABLE_KEYS формами, живое применение через `set`, честные состояния (отказ reload при записи)
- [ ] Модели: браузер HF (перенос из egui: каталог/поиск/VRAM/докачка), список установленных, активная модель, удаление неактивной
- [ ] Трей: toggle окна по клику, старт/стоп, отмена, настройки, выход; иконка состояния; закрытие окна = в трей
- [ ] Hotkey-экран: показать комбинацию, перезапись с предупреждениями, определение пути (evdev vs адаптер)

### Add After Validation (v1.x)

- [ ] Быстрое переключение модели из дашборда/трея — когда станет ясно, что модель реально меняют чаще раза в месяц
- [ ] Визуальная калибровка тишины — после первого потока «порог срабатывает слишком рано/поздно»
- [ ] Диагностика окружения + onboarding-чеклист — после первых установок не на машине автора
- [ ] Словарь/initial prompt — нужен лёгкий extension демона (один ключ); после подтверждения ценности словарём пользователя
- [ ] Таблица paste_keys по приложениям — паритет с фокус-механикой dicta

### Future Consideration (v2+)

- [ ] Потоковый показ текста во время распознавания — переделка inference демона; главный кандидат на «следующую большую фичу»
- [ ] Модели по языкам / маршрутизация — WM Keyboard-паттерн (pin + fallback-цепочка)
- [ ] Повторная обработка старых диктовок — только если появится опциональное хранение аудио
