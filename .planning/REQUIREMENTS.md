# Requirements: dicta — веха v1.1 «Dicta App»

**Defined:** 2026-11-22
**Core Value:** Нажал хоткей — заговорил — текст оказался в курсоре. Быстро и предсказуемо.

## v1 Requirements

Требования вехи v1.1: Flutter-приложение `dicta-app` (дизайн в духе FlClash) поверх существующего
демона + Windows-каркас с рабочей диктовкой. Протокол демона и существующие клиенты не ломаются.

### Каркас приложения (APP)

- [ ] **APP-01**: Приложение dicta-app (Flutter 3.50) собирается и запускается на Linux, показывает оболочку с сайдбаром (Дашборд/История/Модели/Настройки) и работает в тёмной/светлой теме Material You (dynamic_color)
- [ ] **APP-02**: Приложение подключается к демону через существующий unix-сокет и поллинг `status` (100 мс) через изолированный Dart-сервис; при смерти демона показывает «демон недоступен» и переподключается без перезапуска приложения
- [ ] **APP-03**: Платформенная развилка спрятана за интерфейсом DictaEngine — UI не знает о транспорте; Linux-реализация говорит с демоном, Windows-реализация подставляется без изменений UI
- [ ] **APP-04**: Модель настроек в Dart десериализует ответ демона один-в-один (все 17 изменяемых ключей), golden-тест фиксирует fixture JSON демона
- [ ] **APP-05**: Интерфейс на русском (gen-l10n, ru-шаблон), без хардкода строк в виджетах
- [ ] **APP-06**: Все записи настроек идут только командой `set` (валидация остаётся в демоне), jsonEncode вместо ручного экранирования

### Дашборд записи (DASH)

- [ ] **DASH-01**: Пользователь видит состояние демона (запись/распознавание/пауза/ошибка), живой уровень сигнала (~10 Гц) и время записи
- [ ] **DASH-02**: Пользователь запускает/останавливает/отменяет запись кнопками; во время распознавания отмена честно недоступна («распознаю…»), после стопа — спиннер до Idle
- [ ] **DASH-03**: Пользователь видит последний распознанный текст и может скопировать его или вставить заново (`inject`)
- [ ] **DASH-04**: Пользователь калибрует порог тишины графически: гистограмма живого уровня с подвижной отметкой min_level и применением по отпусканию

### История диктовок (HIST)

- [ ] **HIST-01**: Приложение пассивно накапливает диктовки (переходы Transcribing→Idle с новым текстом из status-потока) в локальный store; протокол демона не меняется
- [ ] **HIST-02**: Пользователь листает журнал диктовок и ищет по тексту
- [ ] **HIST-03**: Пользователь копирует запись, вставляет её заново (`inject`) или удаляет из журнала
- [ ] **HIST-04**: Ограничение MVP зафиксировано в docs: история пишется только пока приложение открыто/в трее

### Настройки и модели (CONF, MODEL)

- [ ] **CONF-01**: Пользователь меняет все 17 изменяемых ключей формами (слайдеры/чекбоксы/селекты) с живым `set` и без спама запросами
- [ ] **CONF-02**: UI честно отражает состояния: отказ reload при записи («модель загружается…»), предупреждение перед ключами, требующими перезагрузки движка
- [ ] **MODEL-01**: Пользователь скачивает модели из HF-браузера в приложении: каталог проверенных, поиск с фильтрами (ASR/сортировки/пагинация/подпапки), VRAM-лимит, прямая ссылка, прогресс и докачка (.part)
- [ ] **MODEL-02**: Пользователь видит установленные модели, активную пометку и может удалить неактивную модель

### Трей и хоткеи (TRAY, HK)

- [ ] **TRAY-01**: Приложение сворачивается в трей (SNI): start/stop/отмена/настройки/выход в меню, левый клик = показать/скрыть окно, иконка отражает состояние записи
- [ ] **TRAY-02**: Закрытие окна сворачивает в трей, а не убивает приложение; честный выход — пунктом меню
- [ ] **HK-01**: Экран хоткея показывает текущую комбинацию, путь срабатывания (evdev vs DE-адаптер) и честно предупреждает «применится после рестарта демона»
- [ ] **HK-02**: Приложение НЕ регистрирует глобальный хоткей записи на Linux — он уже в демоне; дубль запрещён (гонка двойного stop)

### Диагностика окружения (DIAG)

- [ ] **DIAG-01**: Пользователь видит onboarding-чеклист состояния окружения: демон жив, сокет отвечает, хоткей-путь работает, модель найдена и загружена, вставка работает — с зелёными/красными пунктами и подсказкой починки

### Windows-каркас (WIN)

- [ ] **WIN-01**: GitHub Actions workflow `windows-build.yml` собирает zip-артефакт приложения на windows-раннере и зелёный на ПУСТОМ скелете — до любого кода фич
- [ ] **WIN-02**: Windows-сборка приложения показывает ту же оболочку и подключается к движку через выбранную фазой развилку (по умолчанию named pipe `\\.\pipe\dicta` с тем же JSON-протоколом; решение подтвердить в plan-phase)
- [ ] **WIN-03**: Пользователь на Windows диктует: захват микрофона (cpal/WASAPI, 16 кГц mono) → whisper.cpp → та же модель/конфиг, запись по RegisterHotKey без открытия окна
- [ ] **WIN-04**: Вставка текста на Windows: SendInput (KEYEVENTF_UNICODE) с буфером через delayed render (SetClipboardData(NULL) + WM_RENDERFORMAT), оптаут-форматы Win+V/облака, восстановление исходного буфера; обязательные тест-кейсы: обычное окно, elevated-окно (UIPI), зажатый модификатор, Chromium-окно
- [ ] **WIN-05**: Пути конфига/моделей на Windows — %APPDATA%/%LOCALAPPDATA%, без хардкода юниксовых путей; named pipe защищён DACL текущего пользователя

### Декомиссия (RETIRE)

- [ ] **RETIRE-01**: Пользователь подписывает чек-лист паритета dicta-app с dicta-settings (все поля, браузер моделей, валидация, честные состояния) — после чего dicta-settings удаляется из репо

## v2 Requirements

Отложено (осознанно, с обоснованием в исследованиях):

### Будущее ядро

- **FUT-01**: Потоковый показ текста во время распознавания — требует переработки inference-конвейера
- **FUT-02**: Быстрое переключение модели из дашборда/трея — не выбрано в веху пользователем
- **FUT-03**: JSONL-история в демоне (сейчас — пассивный захват в приложении, без изменения протокола)
- **FUT-04**: Модели по языкам/маршрутизация, повторная обработка старых диктовок
- **FUT-05**: Полный паритет Windows (все режимы вставки, эквивалент оверлея)
- **FUT-06**: macOS/Android-сборки (Flutter делает возможным)

## Out of Scope

| Feature | Reason |
|---------|--------|
| Облачный STT / AI-постобработка LLM | dicta — local-first; ценность — приватность и предсказуемость |
| Запись встреч / файловая транскрипция / хранение аудио | Это другой продукт; размывает ядро |
| Свободный редактор config.toml | Валидация принадлежит демону; UI-формы достаточны |
| Статистика WPM / «геймификация» | Анти-фича по исследованию (bloat) |
| Изменение протокола демона в этой вехе (subscribe/события) | Жёсткое ограниждение PROJECT.md; поллинг достаточен, шов DictaEngine оставляет дверь открытой |
| Копирование GPL-кода FlClash | Лицензионная контаминация; паттерны/дизайн — да, код — нет |
| FRB (flutter_rust_bridge) в этой вехе | Ломит схему «приложение = клиент демона»; пересмотреть при мобильной вехе |
