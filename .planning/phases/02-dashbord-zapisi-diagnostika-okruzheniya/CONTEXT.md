# CONTEXT — Phase 2: Дашборд записи + диагностика окружения

## Формулировки требований (из REQUIREMENTS.md)

- **DASH-01**: Пользователь видит состояние демона (запись/распознавание/пауза/ошибка), живой
  уровень сигнала (~10 Гц) и время записи.
- **DASH-02**: Пользователь запускает/останавливает/отменяет запись кнопками; во время
  распознавания отмена честно недоступна («распознаю…»), после стопа — спиннер до Idle.
- **DASH-03**: Пользователь видит последний распознанный текст и может скопировать его
  или вставить заново (`inject`).
- **DASH-04**: Пользователь калибрует порог тишины графически: гистограмма живого уровня
  с подвижной отметкой min_level и применением по отпусканию.
- **DIAG-01**: Пользователь видит onboarding-чеклист состояния окружения: демон жив,
  сокет отвечает, хоткей-путь работает, модель найдена и загружена, вставка работает —
  с зелёными/красными пунктами и подсказкой починки.

## Замеченные решения (locked, из PROJECT.md / фазы 1)

1. Протокол демона заморожен: только существующие команды status/start/stop/cancel/
   inject/set/settings; никаких правок crates/*. Ответ демона
   `{"base":{state,level,seconds,text,error},"panel":bool,"settings":{...}?}`.
2. IPC-клиент уже существует: `app/lib/core/daemon_engine.dart` (DictaEngine interface,
   свежее соединение на команду, таймауты status 2s / set 30s / stop 120s) +
   `providers.dart` (DictaStatusNotifier: Timer.periodic 100 мс — уже даёт ~10 Гц для
   DASH-01, backoff 200 мс→2 с при недоступности).
3. Диагностика — только через существующие команды демона и локальные проверки (сокет
   существует, state отвечает); новых команд демону НЕ добавлять. «Хоткей-путь работает»
   проверять без отправки команд: конфиг demона не читается приложением напрямую
   (протокол не имеет get hotkey) — пункт чеклиста должен опираться на то, что доступно:
   например, состояние демона (state живой) и совет «проверь хоткей вызовом dictactl
   toggle» как подсказка, без фактического дергания хоткея.
4. UI-слой: Material You shell из фазы 1 (`features/shell/shell.dart`, NavigationRail
   Дашборд/История/Модели/Настройки, заглушки на местах). Новые экраны — файлы в
   `app/lib/features/dashboard/`, состояние — Riverpod поверх DictaEngine.
5. Русский UI только через gen-l10n (`l10n.yaml`, output lib/l10n/generated);
   кириллица в lib/ вне generated/comments запрещена гейтом
   `app/tool/cyrillic_gate.sh` (следить: новые строки в .arb).
6. `inject` (DASH-03) — команда демона «вставить последний текст заново»; кнопка
   «скопировать» — Clipboard Flutter (Clipboard.setData), это локально, без демона.
7. Честность кнопок (DASH-02): отображаемое состояние — `base.state` из status-поллинга;
   во время `transcribing` отмена недоступна (демон честно держит stop-соединение до
   конца вставки — UI должен дождаться ответа, не таймаутить UX: после stop ждать
   следующего status-тика, спиннер «распознаю…»).
8. Калибровка min_level (DASH-04): гистограмма живого уровня (сэмплы `base.level` из
   поллинга) + отметка текущего порога; отправка `set min_level` — по отпусканию
   ползунка (паттерн фазы 1: без спама, одна команда на жест).
9. Уровень сигнала `base.level` — float 0..1 (уровень тишины относительно порога в
   существующем Rust-коде; verify: заглянуть в panel.rs как рисует уровень — тот же
   источник). Секунды записи `base.seconds` уже в ответе status.

## Scope fences (что НЕ в этой фазе)

- История диктовок — фаза 3; настройки/модели — фаза 4; трей/хоткеи — фаза 5.
- Стриминг текста, JSONL-журнал, правки демона — вне вехи (PROJECT.md Out of Scope).
- Новые зависимости: по возможности нулевые; особые Dart-пакеты для графиков
  не вводить — гистограмма рисуется стандартными виджетами (CustomPainter/LayoutBuilder).

## Открытые вопросы, которые план должен закрыть сам

1. Тик поллинга 100 мс — достаточно для «~10 Гц» DASH-01? (Да: level приходит в каждом
   status-ответе; UI-перерисовка по StateNotifier.)
2. Как определить «вставка работает» в DIAG-01 без фактической вставки в чужое окно?
   (Пункт помечать как «проверяется вручную» с подсказкой, либо честно: только сокет+
   модель живые автоматически; вставка — рекомендация пользователю проверить хоткеем.)
3. Формат гистограммы: окно последних N сэмплов уровня в памяти notifier'а (не persist).

## Проверенные факты (сверено с кодом демона 2026-11-22)

- **Состояния демона — только три: idle / recording / transcribing** (dictad main.rs:94-96).
  «Паузы» нет — UI показывает только реальные состояния, без выдумки.
- **`inject` требует явный непустой текст** ≤5000 символов (dictad main.rs:881-887):
  приложение шлёт `{"cmd":"inject","text": последний текст}` (last_text демона
  обновляется этой же командой; пустой/длинный текст → error в ответе).
- Команды демона: status/start/stop/toggle/cancel/inject/panel/settings/set — все живые.
- `base.seconds` уже в каждом status-ответе — время записи не считаем в UI локально.
