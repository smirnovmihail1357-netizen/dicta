# Phase 3: История диктовок — UAT (живые проверки)

_Статус: testing. Автопроверки фазы зелёные (батарея 71/71, analyze 0, cyrillic 0,
контракты целы) — остаются три проверки, требующие живого микрофона, живого демона
и человеческих глаз. Выполняются пользователем; результаты вписать ниже._

## UAT-3-1: Живая диктовка через приложение → запись в журнале

**Шаги:**
1. Запусти dicta-app при живом демоне (сокет `/run/user/1000/dicta.sock`).
2. Нажми «Запись», продиктуй пару фраз, нажми «Стоп».
3. Открой вкладку «История».

**Ожидание:** продиктованный текст появился в журнале с таймстампом HH:mm,
новые записи сверху. Затем перезапусти приложение → журнал пуст
(честное MVP-ограничение: память, не диск).

## UAT-3-2: Хоткейная диктовка демона НЕ попадает в журнал (принятие ограничения A4)

**Шаги:**
1. При открытом dicta-app сделай диктовку ГЛОБАЛЬНЫМ хоткеем демона
   (как обычно, без приложения).
2. Открой вкладку «История».

**Ожидание:** запись НЕ появилась — наблюдаемое ограничение A4: протокол
возвращает текст только в ответах на собственные команды приложения
(README.md: «never enter the journal»).

## UAT-3-3: Поиск / копия / re-insert / удаление глазами

**Шаги:**
1. Накопи 3+ записи в журнале (можно повторными диктовками UAT-3-1).
2. Введи в поиск часть слова в ДРУГОМ регистре (например «МИР») → находится;
   кривой запрос → «ничего не найдено»; очисти поиск → все записи видны.
3. «Скопировать» → текст в буфере обмена (вставь куда-нибудь для проверки).
4. «Вставить заново» → текст вставился в активное окно; во время выполнения
   кнопка недоступна (busy).
5. «Удалить» → запись исчезла; «Отменить» в снеке возвращает её на место.
