## U-1. Оболочка и баннер «демон недоступен» на Windows (SC3, WIN-02)

**Шаги:**
1. Скачать артефакт `dicta-app-windows-x64` из run `45053175664`
   (или новее на ветке `windows`): `gh run download 45053175664 -D win-artifact`
2. Распаковать ВЕСЬ zip (не только exe) в папку.
3. Запустить `dicta_app.exe`. Пайп-сервер фазы 7 ещё не существует — это ожидаемо.

**Ожидаемо:**
- Оболочка стартует (из трея), тот же сайдбар: Дашборд / История / Модели / Настройки.
- Тёмная/светлая темы Material You переключаются (паритет с Linux).
- Баннер «демон недоступен» — то же поведение, что на Linux без демона (канон фазы 1);
  подключение ретраится, приложение не крашится и не зависает.
- Трей-иконки (idle/recording) на месте.

**Почему human:** визуальный паритет GUI и runtime-поведение на Windows не автоматизируемы
без машины; CI доказывает сборку и состав артефакта, не поведение процесса.

## U-2. Пути живого процесса: %APPDATA% / %LOCALAPPDATA% (SC4, WIN-05)

**Шаги:**
1. На той же машине с запущенным dicta_app.exe открыть Process Monitor (ProcMon),
   фильтр по процессу `dicta_app.exe`.
2. Положить тестовый `config.toml` в `%APPDATA%\dicta\config.toml` (с валидным hotkey-ключом)
   и проверить, что карточка диагностики его видит.
3. Просмотреть обращения к файловой системе.

**Ожидаемо:**
- Процесс читает `%APPDATA%\dicta\config.toml`.
- Модель ищется в `%LOCALAPPDATA%\whisper-cpp`.
- НИ ОДНОГО обращения к `/run/user`, `~/.config`, `XDG_*` (юникс-хардкодов в Windows-ветках нет —
  подтверждено grep-гейтом; здесь проверяется фактическое окружение живого процесса).

**Почему human:** пути кода покрыты injectable-фейк-тестами (windows_paths_test.dart, 10 тестов,
все зелёные), но Platform.environment живого процесса наблюдаем только на живой машине.

## U-3. Подключение к живому пайп-серверу (SC3 остаток; фаза 7)

**Шаги (после появления сервера фазы 7):**
1. Запустить пайп-сервер фазы 7 (Rust, `interprocess`, DACL по контракту из README).
2. Запустить dicta_app.exe.
3. Проверить connected-статус, старт/стоп/инъекцию.

**Ожидаемо:**
- Оболочка переключается с баннера на connected-статус через `\\.\pipe\dicta`.
- Тот же JSON-line протокол: status/start/stop/inject/set работают без изменений протокола.

**Почему human:** в фазе 6 сервера не существует (locked decision 2 — демон на Windows не
портируется до фазы 7); подключение к живому пайпу непроверяемо ранее фазы 7. Этот пункт
может быть поглощён UAT фазы 7.
