## UAT-7-1. Живая диктовка: хоткей без окна → фраза → текст (WIN-03 backstop)

**Шаги:**
1. Запустить `dictad.exe` (артефакт 45066485292) с конфигом, где `hotkey = "alt+v"`
   (или другой спекой; env-шов `DICTA_HOTKEY` тоже работает; `"off"` — гейт).
2. Убедиться, что НИКАКОЕ окно не открывается (RegisterHotKey hWnd=NULL, MS-семантика).
3. Физически нажать хоткей → проговорить короткую фразу → нажать хоткей повторно.
4. Наблюдать распознавание (окно демона не появляется; прогресс виден только через
   подключённое приложение — UAT-7-2 — либо по логу демона, где текста диктовки НЕТ).
5. Повторить с занятой комбинацией (например, зарезервированной ОС) и с невалидной спекой.

**Ожидаемо:**
- Диктовка стартует/останавливается по физическому нажатию, окно не создаётся.
- Захват идёт на native-конфиге WASAPI (НЕ тишина — Pitfall 1), первый канал,
   децимация в 16 кГц на stop; whisper.cpp распознаёт текст **той же моделью/конфигом**,
   что на Linux (roadmap SC п.1).
- Аудио существует ТОЛЬКО в памяти: ни одного temp-WAV/файла на диске (ProcMon-фильтр
  по dictad.exe не должен показать записей аудио).
- Занятая комбинация → честная русская ошибка с win32-кодом (GetLastError), backoff-ретрай
  при освобождении; невалидная спека → честная «не клавиша».
- `inject`/вставка на этом этапе даёт честную ошибку «вставка появится после спика
  (07-02)» — это ожидаемо (Must-NOT 8), не провал.

**Почему human:** живой звук WASAPI и доставка WM_HOTKEY в очередь потока живой
интерактивной сессии; CI-раннер без аудио-устройств, unit-тесты покрывают только
чистые функции (парсинг спеки, кламп F32→i16, overflow-порог).

## UAT-7-2. Подключение Flutter-приложения к живому Windows-демону (поглощает 06-UAT U-3)

**Шаги:**
1. Запустить `dictad.exe` (пайп-сервер `\\.\pipe\dicta`, DACL owner-SID).
2. Запустить `dicta_app.exe` (артефакт фазы 6).
3. Проверить connected-статус, кнопки старт/стоп, живой уровень.
4. `taskkill /f dictad.exe` → дождаться баннера → запустить демон снова.

**Ожидаемо:**
- Оболочка переключается с баннера «демон недоступен» на connected-статус через
  `\\.\pipe\dicta` (06-UAT U-3 закрыт: сервер фазы 7 теперь существует).
- Тот же JSON-line протокол: status/start/stop/set работают без изменений протокола
  (framing/golden фаз 1-6 не тронуты — подтверждено верификатором).
- После kill демона баннер появляется с ПРИЧИНОЙ отключения (IN-02 poll-ветка,
  runtimeType без payload); повторный запуск демона → автопереподключение.
- Карточка хоткея: живой ответ демона отображается; ошибка протокола — честный
  AsyncError, а не молчаливый файл-фолбэк (IN-02).

**Почему human:** живое межпроцессное подключение двух процессов на Windows-десктопе;
CI pipe_roundtrip доказал демон-сторону (клиент → пайп → serve_conn → JSON status),
но не Flutter-клиента поверх живого пайпа. Поглощение: пункт U-3 фазы 6
(06-UAT.md, «может быть поглощён UAT фазы 7») закрывается здесь.
