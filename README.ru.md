# dicta (Русский)

Системный голосовой ввод для Wayland/Linux: один демон вместо отдельной интеграции в каждое
приложение.

`Alt+V` (или `dictactl toggle`) -> говоришь -> `Alt+V` ещё раз -> текст появляется там, где
курсор: Kate, Konsole, Firefox, Discord, чат в браузере, промпт pi/opencode.

Остановка — это **тот же Alt+V** (или клик по пилюле, или `dictactl stop`), не Enter.
Отмена без распознавания — `dictactl cancel` (клавишу для него назначить самому:
`DICTA_CANCEL_KEY='Meta+Shift+Escape' ./adapters/kwin/install.sh`).

## Состав

| crate | что делает |
|---|---|
| `dicta-core` | конфиг (TOML), запись (PipeWire), распознавание (whisper-rs: Vulkan/CPU), фильтр галлюцинаций, вставка (wl-copy + uinput), клавиши по окнам |
| `dictad` | демон: Unix-сокет, запись, инференс, вставка текста в фокусное окно, порождает оверлей |
| `dictactl` | CLI: `toggle`, `start`, `stop`, `cancel`, `status`, `paste-keys`, `calibrate`, `inject <текст>`, `infer file.wav`, `atspi-dump`, `atspi-insert <текст>` |
| `dicta-ui` | layer-shell оверлей: пилюля REC + волна уровня + анимация распознавания; пилюля выезжает из-под нижней кромки экрана |
| `dicta-settings` | отдельное окно настроек (eframe/egui): запись, модель, вставка, система |
| `adapters/` | горячие клавиши: KWin-скрипт (Plasma 6), Hyprland, sway, Quickshell, GNOME |
| `systemd/` | user-сервис `dictad.service` + oneshot-юниты, которые дёргает DE |

Цепочка: горячая клавиша DE -> oneshot-юнит systemd -> `dictactl toggle --app <окно>` -> демон
(`pw-record` -> whisper -> фильтр) -> `wl-copy` + синтез клавиш через `/dev/uinput`.

Оверлей не возникает мгновенно: пилюля выезжает из-под нижней кромки экрана (46 px,
пружинная кривая с overshoot'ом, ~260 мс) и проваливается обратно за кромку, когда запись
закончена (~170 мс). Длительности — `DICTA_ANIM_MS` и `DICTA_ANIM_OUT_MS`, `DICTA_ANIM=0`
выключает анимацию совсем. Кадры анимации можно смотреть и без композитора:
`dicta-ui --preview out/` пишет их в BMP.

## Установка на хост

```bash
git clone https://github.com/<you>/dicta.git && cd dicta
make build                      # release-сборка с Vulkan
make install                    # -> ~/.local/bin/{dictad,dictactl,dicta-ui}
./tools/fetch-model.sh          # ggml-модель в ~/.local/share/whisper-cpp/
mkdir -p ~/.config/dicta && cp config.example.toml ~/.config/dicta/config.toml
./systemd/install.sh            # dictad.service + юниты toggle/cancel
./adapters/kwin/install.sh      # Plasma 6: Alt+V через KWin-скрипт (нужен выход/вход в сессию)
systemctl --user start dictad.service
```

Дальше: `Alt+V`, говорить 3–4 с, `Alt+V`. Что именно произошло — видно в журнале:
`journalctl --user -u dictad.service -f`.

Сборка без Vulkan (не нужен glslangValidator; в конфиге `use_gpu = false`):
`make build-cpu`.

Тайминги вставки: `paste_delay_ms` — не фиксированная пауза, а потолок ожидания готовности
буфера после `wl-copy`; клавиши посылаются сразу после подтверждения. Прежнее содержимое
буфера возвращается в фоне через `clipboard_restore_ms`, поэтому демон отвечает и уходит
в idle сразу после нажатия клавиш, не дожидаясь восстановления.

## Диагностика и подбор порога

```bash
dictactl status                      # состояние и уровень
dictactl calibrate --secs 8          # 8 с говоришь: пик речи, среднее, уровень первых 2 с
dictactl inject "проверка вставки"   # вставляет текст без микрофона
dictactl inject --app konsole "…"    # принудительно клавиши терминала
dictactl atspi-dump --depth 8          # AT-SPI: приложения, роли, фокус, тайминги этапов
dictactl atspi-insert "текст"          # проверка AT-SPI-вставки напрямую, мимо демона
./tools/insert-test.sh               # сквозная проверка вставки в отдельное окно
journalctl --user -u dictad.service -f
```

Если диктовка «пропускается» — крути `min_level` (по умолчанию 0.35; 0.25 чувствительнее,
0.6 строже). Гейтер считает не среднее по всему аудио, а максимум по окнам 300 мс.

По умолчанию запись закрывается только горячей клавишей (`auto_stop = false`) — тишина её
не обрывает. Поставь `auto_stop = true`, если хочешь, чтобы демон закрывал запись сам:
монитор уровня работает watchdog'ом и останавливает запись через `auto_stop_after_ms` тишины,
с передышкой `auto_stop_grace_ms` в начале. Жёсткий потолок `max_record_ms` действует в
обоих случаях.

## Вставка без буфера обмена (`inject_mode = "atspi"`)

Режим `paste` пишет буфер обмена и нажимает клавиши. Режим `atspi` пишет прямо в фокусный
виджет через AT-SPI2 (`org.a11y.atspi.EditableText`) — буфер обмена не трогается, клавиши не
синтезируются. Сборка с фичей:

```bash
cargo build --release --features dictad/atspi,dictactl/atspi
```

Поддерживает ли нужное окно такой путь — проверяется `dictactl atspi-dump`, ничего не
вставляя:

```bash
dictactl atspi-dump --depth 8          # приложения, роли, фокусные объекты, тайминги этапов
dictactl atspi-dump --app firefox --tree
```

Писать демон разрешает только объектам с ролью поля ввода (`entry`, `password text`,
`combo box`, `text`). Это важно: Firefox помечает `focused` узел `document web` (и он правда
реализует `EditableText`) — а это не «фокусное поле». `atspi_allow_any_role = true` имеет
смысл только при диагностике такого окна. Поддержка AT-SPI разная по тулкитам: Gecko/GTK —
да, Qt требует `QT_ACCESSIBILITY=1`, Chromium/Electron — `--force-renderer-accessibility`.

## Горячая клавиша

Полная инструкция — в [`adapters/README.md`](adapters/README.md).

| Композитор | как |
|---|---|
| KDE Plasma 6 | `./systemd/install.sh && ./adapters/kwin/install.sh` (`Alt+V`; `Meta+V` занят историей буфера обмена Plasma 6) или System Settings -> Keyboard -> Custom Shortcuts -> `systemctl --user start dicta-toggle.service` |
| Hyprland | `source = .../adapters/hyprland/dicta.conf` |
| Sway | `include .../adapters/sway/dicta.conf` |
| GNOME | `./adapters/gnome/apply.sh '<Ctrl><Alt>v'` |
| любой DE/без DE | evdev-слушатель демона: `hotkey = "ctrl+alt+v"` + доступ к `/dev/input/event*` |

Панель настроек: `Ctrl+Alt+V` (KWin), `SUPER SHIFT, S` (Hyprland), `$mod+Shift+s` (sway),
`dicta-panel.service` (любой DE) или просто `dictactl panel`.

## Панель настроек

`Ctrl+Alt+V` (KWin; клавиша настраивается через `DICTA_PANEL_KEY` в `adapters/kwin/install.sh`)
открывает над пилюлей панель кнопок: запись/стоп, отмена, порог `min_level` (−/+), авто-стоп,
режим вставки, GPU, язык, модель, клавиши вставки, «закрыть». Открыта панель или нет решает
демон, оверлей только рисует — поэтому её можно открыть и из терминала: `dictactl panel`.

Клик по кнопке — это одна команда демону (`{"cmd":"set","key":...,"value":...}`): демон сам
проверяет значение, применяет его к живому конфигу и пишет в `~/.config/dicta/config.toml`,
сохраняя комментарии и порядок ключей. Строка внизу панели — ответ демона: что сохранено или
почему отказали.

```bash
dictactl panel                    # показать/скрыть
dictactl panel --state show       # то же, что Ctrl+Alt+V
dictactl settings --json          # снимок настроек + список .bin моделей
dictactl settings min_level 0.4   # то же, что кнопка «min +»
dictactl settings model ggml-large-v3-turbo-q5_0   # имя ищется в папке моделей
```

`model`, `language`, `use_gpu`, `gpu_device`, `n_threads`, `beam_size` требуют заново загрузить
модель: демон делает это отдельным потоком и отказывает, пока идёт запись или распознавание
(на панели в это время подпись «модель загружается…»). Повторная установка того же значения
ничего не перезагружает и не переписывает.

## Окно настроек

Для полного набора настроек есть отдельное окно `dicta-settings` (eframe/egui) с четырьмя
вкладками: «Запись», «Модель», «Вставка», «Система». Слайдеры отправляют значение, когда
ползунок отпущен (не на каждый кадр перетаскивания), чекбоксы и подписи — по клику. Демон
проверяет значение, применяет его к живому конфигу и пишет в `~/.config/dicta/config.toml`;
ответ сразу виден в окне: отклонённое значение выделено красным внизу, а перезагрузка модели
подписана «модель загружается…». Панель оверлея остаётся — быстрая запись по-прежнему под рукой.

Вкладка «Модель» умеет скачивать ggml-модели прямо с Hugging Face тремя способами:

1. **Быстрый выбор (проверенные)** — шесть моделей whisper.cpp из встроенного каталога (рядом
   примерный размер и короткая подсказка), нажми «скачать»;
2. **Браузер Hugging Face** — при открытии вкладки сразу загружаются лучшие ASR-модели. Фильтр по
   названию (пусто = все ASR), сортировка по скачиваниям, лайкам или обновлению, чекбокс «только
   распознавание речи» (смена сортировки/фильтра — сразу новый запрос). Результат выглядит как
   `id — N скачиваний · N лайков`, кнопка «показать ещё» дописывает следующие 20. Клик по
   репозиторию открывает подпапки («← на уровень вверх» — назад); `.bin` из подпапки кладётся рядом
   с текущей моделью под своим базовым именем;
3. **Прямая ссылка** — вставь произвольный `https://.../resolve/main/<file>.bin`.

Слайдер **лимита VRAM** (2–32 ГБ, по умолчанию 24, только для UI — в конфиг не пишется) помечает
файлы больше объёма твоей видеопамяти: ggml-модель занимает в памяти примерно свой размер, поэтому
такой файл подписан «≈N ГБ — больше лимита VRAM», а кнопка скачивания неактивна. «Быстрый выбор»
и прямая ссылка лимитом не ограничиваются.

Поиск и загрузка не блокируют друг друга: это независимые слоты. Когда размер известен
(каталог и файлы репозитория), показывается полоса прогресса; для прямой ссылки — спиннер
со счётчиком уже скачанных мегабайт. `curl` пишет в `.part` и докачивает оборванный файл через
`-C -`; готовый `.bin` кладётся рядом с текущей моделью и сразу появляется в списке выше,
загрузку можно прервать. Из терминала то же для встроенного каталога делает
`tools/fetch-model.sh`.

```bash
dictactl settings                       # открыть окно настроек
~/.local/bin/dicta-settings             # или запустить напрямую
dictactl settings --json                # вывести снимок в stdout вместо окна
dictactl settings min_level 0.4         # как и раньше: изменить настройку из терминала
```

При желании повесьте на `~/.local/bin/dicta-settings` горячую клавишу: в KDE — Настройки
системы → Комбинации клавиш → Дополнительные сочетания → Правка → Создать → Глобальная
комбинация → Команда/URL. В KWin/Wayland тулкит не может заставить окно быть поверх всех:
правый клик по заголовку → «Поверх всех окон» (KWin запомнит) либо правило Window Rules для
класса `dicta-settings`. Это не индикатор записи: живой уровень и секунды остаются в оверлее.

## Журнал диктовок (dicta-app)

Диктовки, сделанные через `dicta-app` (кнопки «Запись» → «Стоп»), автоматически попадают в журнал с временем. Вкладка «История» показывает их новые сверху, ищет по тексту и позволяет скопировать, вставить заново или удалить запись.

Журнал живёт только в памяти: записи сохраняются, пока запущено приложение, и очищаются при перезапуске.

Диктовки, сделанные глобальным хоткеем демона, в журнал не попадают: протокол возвращает текст диктовки только в ответах на собственные команды приложения.

## Куда поставить пилюлю

Пилюлю можно перетащить мышью: зажми её и потяни — после сдвига на 60 px начинается
перетаскивание. Куда смотрит рывок, там оверлей и встанет: вверх по экрану — к верхней
границе, вправо — к правой, вниз — к нижней. Движение вдоль своей границы только сдвигает
пилюлю вдоль края, а движение за свою границу наружу оставляет её на месте (за кромкой
экрана рисовать нечего). Простой клик без сдвига — то же, что и раньше: остановить запись
и вставить текст.

Снизу и сверху пилюля и панель горизонтальные, слева и справа обе разворачиваются
вертикально, и выезд по-прежнему идёт из-за кромки той стороны, где пилюля стоит.

Положение — сторона, смещение вдоль края и отступ от края (для дока или панели задач) —
сохраняется в `~/.config/dicta/ui.toml` и читается при следующем запуске. То же самое
можно сделать из терминала:

```bash
dicta-ui --list-edges               # где оверлей стоит сейчас
dicta-ui --edge right               # переставить на правую сторону
```

## Трей (dicta-app)

`dicta-app` продолжает работать в системном трее (SNI / StatusNotifierItem). Крестик окна
скрывает его в трей — процесс жив, иконка остаётся. Честный выход — только пункт **«выход»**
в меню трея (`destroy()` вызывается исключительно оттуда). Выход не прерывает активную запись:
её жизненным циклом владеет демон, поэтому запись завершится по хоткею демона или автостопу —
это сделано намеренно.

Меню содержит: «показать/скрыть окно», «начать запись», «остановить», «отмена»,
«настройки» (открывает окно на вкладке «Настройки») и «выход». Иконка синяя в простое
и красная во время записи и распознавания; она едет на уже существующем опросе статуса,
без второго таймера.

**Поведение SNI в Linux:** панель (KDE Plasma) забирает клики по иконке себе и открывает
экспортированное меню любой кнопкой — `tray_manager` на Linux не получает событий клика.
Поэтому «левый клик = доступ к окну» реализован пунктом меню **«показать/скрыть окно»**.
Это принятое отклонение от буквальной формулировки TRAY-01 (решение оркестратора,
2026-11-22) и часть подписи UAT.

GNOME показывает SNI-иконки только с расширением AppIndicator (известное ограничение
пакета); KDE Plasma размещает их нативно.

Глобальный хоткей записи принадлежит демону, а не приложению. Read-only индикатор в
разделе **«Настройки» → «система»** показывает текущую evdev-комбинацию из `config.toml`
(или «не задан (off)» — штатный дефолт демона), статичную таблицу справки по DE
и предупреждение о рестарте демона.

## Статус

Работает: запись, распознавание (Vulkan и CPU), гейтер тишины, авто-остановка записи по
тишине (VAD, по умолчанию выключена), фильтр галлюцинаций, вставка буфером + клавишами с
подбором под окно, AT-SPI2-вставка без буфера обмена и без синтезированных клавиш,
оверлей, цепочка клавиш через KWin, systemd-юниты.

Не сделано: сквозная проверка AT-SPI-вставки в реальном фокусном поле ввода (на этой машине
тест упирался в то, что `focused` у Firefox — документ, а не поле), доступность Qt-окон без
`QT_ACCESSIBILITY=1`, пакеты для других дистрибутивов, macOS/Windows.
